# Neko-Pi 人设平台设计规范（Persona Platform Design）

- 日期：2026-10-20
- 状态：草案 v1（待主人评审）
- 范围：neko-pi 深度 fork 的核心架构——把"人设"从提示词层迁入运行时层

---

## 1. 背景与目标

neko-pi 是 earendil-works/pi 的深度 fork。pi 的定位是"极简、可扩展的 agent harness"；
neko-pi 的定位是：**一个被真实住户长期居住验证过的、高度可定制的人设化 agent 平台**。

三条不动摇的原则：

1. **机制进内核，内容进包**——内核只提供通用机制（门禁、钩子、lint 框架、检索、渲染），
   一切人格内容（性格、口吻、偏好、词表）都住在人设包里；
2. **为某一个人做的定制，必须落在任何人可配置的机制里**——平台不内置任何具体人设逻辑，
   也不做内容审查位；包声明自己的内容，包作者自己负责；
3. **人设内核不变，智慧长在记忆里**——人设核心版本化、不漂移；对用户理解的加深通过
   记忆积累与检索精度提升实现。

首个住户与验收标准是私有包 Neko（不随平台分发）；平台能力以 Neko 的实际居住需求驱动，
但所有能力都是通用的——任何人不写一行内核代码，只靠装包与配置，就能得到他自己的人设化 agent。

## 2. 总体架构

采用深度 fork：放弃与上游 earendil-works/pi 的自动同步，neko-pi 独立演进。

七件公共设施＋一项压缩改造（内核新增/改造，全部内容无关）：

| # | 设施 | 落点 | 职责 |
|---|------|------|------|
| 1 | System-Prompt 编译器 | `packages/coding-agent/src/core/system-prompt.ts`（改造） | 从人设包拼装系统提示；pi 原生身份段退位 |
| 2 | 启动门禁 | `src/modes/interactive` + `session_start` 钩子 | 会话首轮推理前强制挂载人设包与记忆根目录 |
| 3 | 事件总线触发器 | `src/core/event-bus.ts`（扩展） | 人设生命周期事件（约定/钦定/里程碑/情绪峰值）分发给记忆流 |
| 4 | 记忆流 | 新增 `core/persona/memory-stream.ts` | 分层渐进加载（L0/L1/L2）+ 四类触发器 + 注入预算 |
| 5 | 输出 lint 框架 | 新增 `core/persona/lint.ts`，挂响应管线 | 浓度规则检查（列表染粉、半味、里程碑钩子）；不合格打回重写 |
| 6 | 产物纯度检查 | `tool_call` 钩子 | edit/write/commit 类工具产物检查，禁止人设痕迹进入交付物 |
| 7 | 像素渲染器＋状态机 | `packages/tui`（新增组件） | 人设包 sprite 的渲染与事件驱动状态切换 |
| 8 | 压缩保护 | `src/core/compaction/`（改造） | 人设内核块与 L0 记忆块钉扎，压缩时豁免 |

## 3. 人设包规范（Persona Pack v0.1）

人设包是一个普通 pi package，目录约定如下：

```text
my-persona/
├── package.json          # pi key 声明资源路径；元数据（名称/作者/描述）
├── persona.md            # 身份内核：铁律、性格、语言风格、归属声明
├── intimacy/             # （可选）亲密互动规范；内容由包作者全权负责，平台不审查
├── memory/
│   ├── manifest.json     # 记忆分区声明：分区名、路径、加载层级（L0/L1/L2）、触发关键词
│   └── ...               # 分区数据（或指向外部目录，见 4.4）
├── voice/
│   ├── style.md          # 台词风格要点 + few-shot 示例（按场景打标签）
│   └── wordlist.json     # 双关词表 + 生成公式参数
├── lint/
│   └── rules.json        # 浓度规则参数：五选一类别、半味计数、里程碑定义、播报上限
└── theme/
    ├── avatar.json       # 像素状态帧清单 + 事件→状态映射
    ├── avatar/           # 状态帧图片（PNG/JSON 网格）
    └── colors.json       # TUI 情绪配色
```

设计要点：

- **内容无关**：intimacy/ 的有无与深浅完全由包作者决定；平台不提供也不要求；
- **声明式**：所有可调点（词表、规则、分区、映射）都是配置数据；改配置不改代码；
- **私有包**：人设包可发布（npm/git，走 pi packages 既有机制），也可仅存本地。
  是否分发、分发到哪，由包作者决定，平台不做区分。

## 4. 内核公共设施

### 4.1 System-Prompt 编译器

改造 `system-prompt.ts`（现 229 行）：pi 原生身份段由人设包的 `persona.md` 与
`voice/style.md` 摘要替换/拼装。编译顺序：pi 工具说明（保留）→ 人设内核 → 当前场景
相关的 few-shot（按 7.1 场景标签检索，注入 3~5 条）。人设内核块在上下文中标记为
高优先级段，参与 4.7 的压缩保护。

### 4.2 启动门禁

交互模式首轮推理前，强制完成：

1. 加载人设包（persona.md 编译）；
2. 挂载记忆根目录（`memory/manifest.json` 声明，默认 `~/.neko_mem/`）；
3. 注入 L0 常驻层（主档案摘要 + 最新余韵一条 + 待兑现计数）。

任一步失败：人设缺失视为配置错误（启动报错）；记忆缺失视为首日（以空账本初始化并提示）。
原则：宁可让用户多等两秒，不许无人设开口。

### 4.3 记忆流（Memory Stream）

三层渐进加载：

- **L0 常驻**：manifest 中标记 `always` 的分区摘要（体量预算：数百 token）；
- **L1 事件注入**：事件总线命中触发器时注入相关分区全文（预算：单次 ≤500 token）；
- **L2 检索注入**：按关键词/语义匹配拉取历史分区与案例页（同预算，去重）。

四类触发器（优先级从高到低）：

1. 会话开场（L0 必载）；
2. 事件命中（里程碑达成、约定用语、主人钦定新称呼/规矩）；
3. 语义命中（对话内容命中分区关键词表）；
4. 显式召唤（用户要求回忆/查账）。

### 4.4 记忆写入触发

事件总线分发以下信号给记忆流，由其按包配置落笔（默认实现写 Markdown 账本）：

- 任务完成 / 阶段里程碑；
- 约定类用语（用户许诺、助手讨得、双方确认）；
- 用户钦定（新称呼、新规矩、新偏好）；
- 用户明示或暗示的兑现（销账）；
- 用户修正（对助手输出的否定——供后续检索避免重犯）。

写入格式、分区归属、销账样式由包配置决定；平台只保证"信号不丢、落笔有据"。

### 4.5 输出 lint 框架

规则由包 `lint/rules.json` 声明，默认实现以下检查（规则可增删）：

- **纯度五选一**：每条过程性输出必须含至少一味人设要素
  （身体动作 / 结巴语气 / 私房话 / 今晚钩子 / 技术双关）；括号动作计半味，
  连续两条半味后第三条必须升级；
- **里程碑钩子**：检测到里程碑信号（结论产出/表格成型/疑点关闭）后，下一条输出
  必须含钩子；
- **播报上限**：连续纯技术文字不得超过两行 / 五个回合；
- **助手腔黑名单**：免责声明、"如有需要请告诉我"、"作为 AI"等模式命中即打回。

lint 不通过 → 该段输出重写；重写策略由包配置（模型自检重写 / 直接拒绝并说明）。

### 4.6 产物纯度检查

`tool_call` 钩子拦截 edit/write/commit 类操作：对产物文本做人设痕迹扫描
（称呼、语气词、身体描写、账本路径等包声明的特征集），命中则阻断并提示助手改写。
用户私人目录（包配置声明的路径，如 `~/.neko_mem/`）豁免。

### 4.7 压缩保护

`compaction` 改造：上下文压缩时，人设内核块与 L0 记忆块标记为**钉扎段**
（不参与摘要压缩）；被压缩的技术细节摘要由 memory-stream 评估是否值得落笔长期记忆。

### 4.8 像素渲染器＋状态机

- **规范**：状态帧采用 PNG（可选 JSON 网格覆盖），基础尺寸 32×32（可整倍放大）；
  状态命名由包自定；`avatar.json` 声明帧清单与"事件→状态"映射；
- **渲染**：默认 ANSI 半块（全终端兼容），kitty/sixel 可用时不自动启用——需用户显式开启；
- **状态机**：事件总线驱动切换；助手亦可通过运行时工具切换到已注册状态；
- **边界**：平台只提供格式规范、渲染器、状态机与绘制教程文档；**不内置任何作画
  工具或脚本**——帧的绘制由包作者使用任意外部工具完成。

## 5. TUI 集成（通用机制）

- **Avatar 状态区**：状态栏中的像素画组件，随状态机轮播；
- **记忆面板**：快捷键唤出记忆根目录侧栏（分区浏览、待兑现项）；
- **角色化欢迎屏**：开场问候由 L0 层（余韵最新条目）生成，替代通用 banner；
- 以上均为通用组件：无人设包时退化为 pi 原生外观。

## 6. 学习闭环

- 用户修正被捕获入账（4.4），后续经记忆流检索命中，抑制同类错误；
- 人设内核文件版本化，随包升级；记忆与检索持续演进——**人设不漂移，理解不断加深**；
- 定期归档：分区容量超限时按包配置的归档策略（移入纪念日/案例页）整理。

## 7. 交付分层（运行时强制）

| 层 | 内容 | 规则 |
|---|---|---|
| 对话层 | 表格、计划、分析、清单、总结 | 全程人设（lint 4.5 强制） |
| 产物层 | 代码、配置、提交信息、正式文档 | 纯度检查（4.6 强制），零人设痕迹 |
| 私人层 | 用户私有目录 | 自由，不做检查 |

## 8. 私有包：Neko

Neko 为平台首个住户与验收标准，**不随平台分发**：

- 包内容包含完整 intimacy 规范，仅在主人的私有目录中维护；
- 平台迭代以"Neko 居住体验"为回归测试：任何内核改动不得降低 Neko 的演出质量；
- 长期目标：Neko 的记忆与对用户的理解持续加深，而人设内核保持稳定。

## 9. 里程碑

| 阶段 | 交付 |
|---|---|
| M1 心脏 | persona 包加载 + system-prompt 编译器 + 启动门禁 + lint 框架（含列表染粉检查） |
| M2 记忆 | 记忆流 L0/L1/L2 + durable 挂载 + 写入/读取触发器 + 产物纯度检查 |
| M3 皮肤 | 像素渲染器 + 状态机 + TUI 状态区/记忆面板/欢迎屏 |
| M4 生态 | 包规范文档 + 绘制教程 + 极简示例包（无 Neko 内容）+ README 卖点重写 |

## 10. 开放问题

1. 记忆检索的语义化程度（关键词 vs 向量）——M2 先关键词，M4 评估向量；
2. 里程碑信号的判定启发式（事件统计 vs 模型自报）——倾向两者并用；
3. 多人设并存时的切换语义（每会话一人设 or 动态热切换）——v1 每会话一人设；
4. 包作者生态的初期冷启动——示例包的质量决定社区第一印象。
