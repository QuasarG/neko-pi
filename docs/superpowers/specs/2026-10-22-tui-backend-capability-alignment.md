# neko-pi TUI 与 Pi 后端能力对齐规范

- 日期：2026-10-22，Asia/Shanghai。
- 状态：设计草案，供用户审阅；本文不代表功能已实现或验收通过。
- 配套任务：[todo](../tasks/2026-10-22-tui-backend-capability-alignment-todo.md)。
- 基础规范：[分作用域记忆与运行上下文](2026-10-21-scoped-memory-runtime.md)。
- 本次授权范围为编写文档，不修改实现、运行数据、凭据或 Git 状态。

## 1. 目的与取舍依据

将移植前端变成 neko-pi 自己的可靠界面，而不是逐项复刻 OpenCode。保留项目会话树、最近会话和标签页的交互优势；推理、认证、工具、记忆及原生历史以 Pi 的真实能力为准。

例：前端收到带图片的输入，显示了图片附件，但 Bridge 只把 text 传给 Pi。即使 HTTP 返回成功，也不算支持图片。对齐后的结果应当是：支持图片的模型收到完整图片；不支持时明确拒绝，附件和草稿仍保留。

判断一个功能是否支持，必须同时核对入口、请求、后端操作、状态事件和持久化结果。存在组件、返回 200、模型能够通过工具完成类似任务，都不是功能已接通的充分证据。

## 2. 产品边界

1. 所有会话共用一个全局人设，但任务上下文、模型选择、cwd、项目作用域和执行状态各自独立。
2. 保留主要对话布局；右侧保留独立会话卡片，按项目分组并提供最近会话。点击打开或复用顶部标签。
3. Neko 状态、图片及立绘常驻区域继续留空，不加入文本或图形替代物。
4. 产品配置和运行数据使用 `~/.neko_pi` 或显式 `NEKO_PI_HOME`；不另建 `.pi` 或依赖用户安装的 OpenCode 配置。
5. 不访问、迁移或修改 `.neko_mem` 和外部人设母本 AGENTS.md。
6. 已固定的消息、时间、运行快照、工具结果不因本次 UI 对齐重算；沿用基础规范的交付回执、恢复和缓存边界。
7. 不将前端会话切换变成人设切换，不增加每轮额外模型总结调用。
8. 本轮不实现远程配对、worktree 管理、上游持久终端或后台任务平台；也不扩展 RAG、角色图片生成或子代理体系。

## 5. 能力协议和适配层

### 5.1 能力声明

拟增加 `GET /api/neko/capabilities`，返回带协议版本的能力对象。具体类型在实现前核对现有客户端定义，避免另建庞大通用框架。

- 每项明确为 supported、unavailable，或 partial；partial 必须携带可执行子能力和限制。
- 全局功能与会话/模型相关功能分开。例如全局支持图片传输，不代表当前模型接受图片。
- 能力声明与路由使用同一服务判断，不能由前端独立硬编码“已支持”。
- 前端初始化时读取，切换模型、登录、重载或资源变化后刷新相关能力。
- 配置了但连接失败的功能，仍展示其失败状态；不能等同于产品根本未实现而隐藏。
- 请求失败时明确显示连接/协议错误，不回退成“所有功能可用”。

### 5.2 错误和空数据

- 已支持且结果为空的列表，返回该接口规定的合法空结果。
- 未实现的接口返回明确的不支持错误；未知路径返回 404，不统一返回位置封套和空列表。
- 非法参数、未认证、会话不存在、操作冲突分别区分；不把操作接受和操作完成混成一个成功提示。
- 不支持的附件、投递模式或控制字段必须拒绝，不能静默丢弃。
- 正常启动所需的所有请求必须有真实实现，或前端不再发出；不得靠扩大兜底空列表维持启动。

### 5.3 复用 Pi，不复制后端

Bridge 将前端意图映射到 AgentSession、模型运行时、资源加载器和认证存储。已有 RPC 类型可复用语义，但不要求启动第二套 RPC 进程，也不把 RPC 名称直接当作现有 HTTP 路由。

公共 vendored 客户端不是本产品后端事实源。优先在 neko-pi 接入处做窄适配；只有确有共同需要时才调整共享类型，不能为修一个缺口改写全部上游协议。

## 6. 模型、认证和设置

### 6.1 模型和思考强度

1. 模型目录来自与执行使用的同一个注册表，合并内置与用户配置，保留可用性及失败原因。
2. 默认选择复用 Pi 的配置解析规则，不按名称含 flash 或数组位置猜测。
3. 模型 ID、输入类型、工具支持、上下文限制和思考等级均来自真实元数据。
4. 前端“显示思考内容”属于界面设置；“思考强度”属于请求参数，两者分开。
5. 切换和刷新不得只改变标签；最终 provider 请求必须包含相应模型及受支持参数。
6. 无凭据、失效凭据或不可用模型要有可操作错误，不能在首次调用时才暴露无解释失败。

### 6.2 认证

- 登录逻辑复用 Pi provider 的 OAuth/API key 实现，包括其支持的浏览器与设备码交互。
- OAuth 的取消、超时、刷新、失败和退出均有状态，不能只覆盖成功路径。
- 凭据写入现有私有认证存储，不在 URL、日志、SSE、侧栏或模型上下文暴露 access/refresh token。
- 前端只接收必要的登录 URL、设备码和状态；关闭弹窗后停止相应等待，避免回调落到其他会话。
- 不自动导入其他应用凭据，不修改用户现有登录；真实账号验证另行明确执行。

### 6.3 设置

| 分组 | 内容 | 存储与生效 |
| --- | --- | --- |
| 界面设置 | 主题、显示思考、复制、动画、布局 | 沿用 TUI 本地配置；可即时生效的即时更新 |
| 运行设置 | 默认模型、原生支持的自动压缩/重试及队列模式等 | 沿用 Pi 设置；明确全局默认、当前会话覆盖及生效边界 |

不把所有运行设置一次暴露。首批只暴露有清晰读写语义的项目，保存后回读真实值。资源重载和默认设置变化不能静默改变已接收请求或其他运行中的会话。

## 7. 输入、执行与结果

### 7.1 输入事务

输入依次经过：校验能力和附件 → 固定来源会话/cwd/模型参数 → 按已有接收规则冻结并保存 → 确认接受 → 原生执行 → 真实结果与状态投影。

- 用户原文、附件、技能选择、编辑器选区和隐藏上下文应有明确归属；不把未处理字段当成已经送达。
- 普通文件引用明确是传路径还是快照。首批方案以原生支持方式为准，并在请求中保留来源，避免模型收到不可读的临时前端 URI。
- 图片传递原生支持的内容和类型；大小、读取失败、模型不支持时给出具体错误，草稿可恢复。
- 编辑器选区在相关用户请求前按固定顺序交付，不能后台漂移到其他会话；不可用时关闭对应入口。
- 模型主动使用文件工具与用户附加文件是不同路径，分别验收。

### 7.2 原生控制

| 操作 | 必须实现的语义 |
| --- | --- |
| steer | 进入原生运行中引导路径；只在原生允许的边界消费，不宣称立即打断工具 |
| follow-up | 当前执行结束后开始，沿用原消息身份、时间和固定背景 |
| 队列修改/取消 | 验证来源及状态；重投幂等；已消费的项目给出冲突，不假成功 |
| 压缩 | 调原生 compact，投影开始、完成和失败；保留原生压缩语义和背景回执失效机制 |
| Shell | 明确直接执行而非让模型解释；取消和输出归原会话，保持既有权限边界 |
| 重载 | 调用原生资源重载；运行中明确拒绝或安排到安全边界，不能改变当前已冻结请求 |

### 7.3 结果和扩展交互

- 文本、思考、工具开始/进度/结束、错误、支持的图片与结构化结果通过明确转换投影；不把缺失内容统一替换成“Tool completed”。
- 扩展交互请求关联会话和请求 ID，区分答复、取消、超时和进程关闭；同一答复不能被其他会话消费。
- 命令执行本身、扩展弹窗和普通模型对话保持区分；没有桥接的命令不能作为普通用户文本误发给模型并假装执行。
- 上游权限组件不自动等同于 Pi 权限系统；必须映射真实权限决策，否则取消暴露，不能返回假授权。

## 8. 会话、导出与界面清理

### 8.1 会话操作

- 原生历史是模型上下文事实源，Bridge 历史是展示投影；用明确 ID 关联，不创造两份可以独立修改的对话事实。
- Pi 原生历史纳入会话目录时，先建立可恢复的映射，不能仅扫描 Bridge JSON 后宣称全部会话可见。
- 分叉前验证消息 ID 与原生 entry ID 的对应边界；新会话保留人设和项目归属，原历史不变。
- 分叉不是文件系统快照，不承诺还原文件；undo/redo 本轮不开放。
- 导出只提供真实支持的格式；若保留前端 Markdown/JSON 导出，则明确其数据结构和脱敏策略，不能把原生 JSONL 假称为相同格式。
- 统计区分实际 token、缓存读写、费用、估计上下文量和未知值。不得用零替代未知；实际供应商缓存命中未实测时注明。

### 8.2 删除无效产品入口

清理范围覆盖命令注册、别名、快捷键、右键菜单、自动补全、状态按钮、帮助、空态提示及能再次打开该功能的间接入口。没有注册的组件源文件不等于用户可见入口，不为了清理文案随意删除共享底层代码。

保留许可和来源声明、依赖包名及必要协议标识；用户可见文案使用 neko-pi。旧配置中仅对应已移除功能的字段按明确规则忽略并记录诊断，不重置有效主题、快捷键或全部配置。

## 9. 验收规则与交付物

1. 每项能力绑定一个真实前端入口、请求及后端调用证据；不能用手动直接 POST 替代全部 UI 联调。
2. 涉及模型请求时使用 harness + faux provider 观察最终请求；不默认使用真实凭据或付费模型。
3. 协议测试覆盖空数据、不支持、失败、取消、重试、跨会话和重启，不能只测返回码。
4. UI 使用真实测试渲染器覆盖键盘、鼠标及宽窄终端；确认状态/图片区域仍为空。
5. 持久化相关验收经过真实原生历史保存，再检查回执和恢复；mock 事件名称不足以证明写入顺序。
6. 任何失败均保留真实错误及未覆盖项；不直接继承旧文档的完成勾选或测试数量。
7. 实施交付包括：实现、定向测试、修订后的能力清单、命令/设置说明、逐项验收证据和已知限制。
8. 本文和 todo 的草案完成不授权开始实施；后续按用户批准的范围推进。不提交、不发布、不推送，除非另有要求。
