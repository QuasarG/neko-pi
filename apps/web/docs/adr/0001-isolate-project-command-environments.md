# Isolate project command environments from the web host

Pi Web sanitizes the environment of the commands it runs directly on the user's behalf instead of exposing the Next.js host runtime wholesale. Direct user shell commands (`!` and `!!` from the composer, `lib/project-command-env.ts`) and the environments of stdio MCP servers remove `PORT`, `NODE_ENV`, `NEXT_*`, and the `PI_WEB_PASSWORD` login secret while preserving the SDK-managed PATH, Pi session metadata, and all other inherited values; explicit variables set by a project command still take effect. The built-in terminal keeps the host environment but also omits `PI_WEB_PASSWORD`. Third-party extensions retain control of their own tools and subprocesses so existing overrides and remote execution integrations are not intercepted.

**Removed (TUI parity):** the model's `bash` tool is no longer shadowed by a Pi Web extension that sanitized its environment. It is pi's core built-in, reading `shellPath` and `shellCommandPrefix` from the shared `~/.neko_pi/settings.json` exactly as in the TUI, and it therefore sees the full host environment — including `PORT`, `NODE_ENV`, `NEXT_*`, and `PI_WEB_PASSWORD`. The web login password is readable through the model's `bash` (e.g. `env`), matching the TUI's full-environment semantics; this reverses this ADR's original hardening for the model's shell and is an accepted regression, not a preserved guarantee.
